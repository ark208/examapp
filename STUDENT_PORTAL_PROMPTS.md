# Student Portal: Antigravity Prompt Playbook

Stack: React (Vite) + Node/Express + PostgreSQL. Desktop only, no webcam. Solo, ~2 days.
Plan: **Part A** builds the whole student frontend on mock data, looking exactly like the teacher portal. **Part B** builds the backend one small step at a time, then connects the two.

Save this file in your repo as `docs/STUDENT_PORTAL_PROMPTS.md`. Every prompt tells Antigravity to read sections 1 and 2 of it, so you don't re-paste the context each time.

---

## How to use this efficiently

1. **One prompt = one fresh task/chat.** Don't chain 3 prompts in one conversation; context gets noisy and quality drops.
2. **Commit after every step that works** (`git add -A && git commit -m "A1 login+dashboard"`). If a step goes bad, `git reset --hard` and re-run the prompt with a fix note.
3. **Test before moving on.** Each prompt has a "Test it" list. Do it. Don't stack untested steps.
4. **Backend prompts ask for a plan first** (files it will touch). Skim it: if it wants to modify teacher routes or rename tables, stop it.
5. **Never let it refactor teacher code** unless the prompt says so. The prompts say "do not change X" for a reason.
6. **When something is wrong**, use the fix template at the bottom instead of re-explaining everything.
7. If your Antigravity has a planning-style mode and a fast mode: use planning for Part B, fast for UI tweaks.

## 1. Context (read by every prompt)

**Project:** online exam portal (JEE style), college project.
**Repo:**
```
examapp/
  frontend/teacher-portal/   (done, Vite + React: pages, components, layouts, context, routes, utils, data)
  frontend/student-portal/   (NEW)
  server/                    (Express + PostgreSQL, shared by both portals)
```
**Teacher flow (already built):** teacher logs in (session cookie) → Question Bank → Create Exam (title, duration, marks, negative marking, questions, assigned students) → Start Exam (only ONE exam live at a time) → Live Monitoring (terminate student / give extra time) → exam ends → auto-submit + evaluation → Results (appeared/absent/submitted/terminated, avg/high/low, CSV).

**Student rules (decided, don't change):**
- Login: roll no. + password. Accounts are created by the teacher (CSV or manual). Passwords are auto-generated by the system and shown to the teacher once. Stored hashed (bcrypt). No self-signup.
- Dashboard lists exams assigned to the student. A "Join/Resume" button is enabled only while that exam is live.
- Question types: `mcq_single`, `mcq_multi`, `numerical`. (No code questions.)
- JEE-style exam room: free navigation + question palette with states: not visited / not answered / answered / marked for review / answered + marked.
- Autosave on every answer change. Heartbeat every 15 s.
- **Server is the only time source.** Server returns `endsAt` and `serverNow`. The client displays `endsAt - (Date.now() + offset)`. Teacher's "extra time" arrives via the next heartbeat.
- One global end time: `endsAt = exam.started_at + duration + attempt.extra_seconds`.
- Proctoring: log `tab_switch`, `window_blur`, `fullscreen_exit`, `copy_paste`. Copy/paste/cut/right-click blocked. Student sees "Warning: this incident has been reported to your teacher." Teacher decides; no auto-terminate.
- Fullscreen: required. Browsers can't truly lock it, so when exited, show an overlay hiding the questions with a "Return to fullscreen" button, and log a violation.
- After the exam the student sees only "Submitted". Terminated students see "Your exam was terminated by the teacher". Reconnecting an in-progress attempt resumes saved answers + remaining time.
- Never send `correct_answer` to the student.

## 2. API contract (the frontend mock and the real backend MUST match this)

All routes under `/api/student`, session-cookie auth, JSON. Errors: HTTP status + `{ "error": "message" }`.

| Route | Body | Returns |
|---|---|---|
| `POST /login` | `{rollNo, password}` | `{id, name, rollNo}` |
| `GET /me` | | `{id, name, rollNo}` or 401 |
| `POST /logout` | | `{ok:true}` |
| `GET /exams` | | `[{id, title, durationMinutes, totalMarks, negativeMarks, examStatus, attemptStatus, attemptId}]` |
| `POST /exams/:id/join` | | `{attemptId}` |
| `GET /attempts/:id/paper` | | see below |
| `PUT /attempts/:id/answer` | `{questionId, answer, state}` | `{ok:true}` |
| `POST /attempts/:id/heartbeat` | | `{status, endsAt, serverNow}` |
| `POST /attempts/:id/violation` | `{type}` | `{ok:true}` |
| `POST /attempts/:id/submit` | | `{status}` |

- `examStatus`: `upcoming | live | ended`
- `attemptStatus`: `none | in_progress | submitted | auto_submitted | terminated`
- `state`: `visited | answered | marked | answered_marked`
- `answer`: mcq_single → `"B"`, mcq_multi → `["A","C"]`, numerical → `12.5`, none → `null`
- `type` (violation): `tab_switch | window_blur | fullscreen_exit | copy_paste`
- `endsAt`, `serverNow`: ISO strings

Paper response:
```
{
  attempt: { id, status, endsAt, serverNow },
  exam: { title, totalMarks, negativeMarks },
  questions: [ { id, type, text, options: [{key:"A", text:"..."}], marks } ],   // options empty for numerical
  answers: { "<questionId>": { answer, state } }
}
```
